Pourquoi ce plugin

Sur une boutique WooCommerce, chaque besoin d'engagement client (cookies, accessibilité, panier, vidéos produit) est habituellement couvert par un plugin séparé — autant de widgets flottants qui s'accumulent et finissent par se chevaucher à l'écran. Saito Navi regroupe quatre de ces besoins derrière un seul bouton (icône engrenage, coin de l'écran), et centralise tous les réglages sur une seule page du Back Office : Navi > Navi.

🍪Consentement cookiesBannière RGPD, Google Consent Mode V2
♿AccessibilitéLangue, taille du texte, contraste
🛒Panier automatiquePanneau sticky sur la fiche produit

Chaque module s'active ou se désactive indépendamment ; désactivé, il n'affiche plus rien côté visiteur.

Où tout se configure

Un seul menu dans le Back Office : Navi > Navi. La page est organisée en onglets — Général (position du bouton, langue, couleurs, arrondis) puis un onglet par module, chacun portant à la fois son interrupteur d'activation et ses propres réglages.

💡 Chaque onglet a sa propre URL avec ancre (ex. #stories) : un lien direct vers un onglet précis peut être partagé ou mis en favori.

🍪 Consentement cookies

Bannière RGPD, modale de préférences, Google Consent Mode V2.

Affiche une bannière de consentement en bas de page (texte, lien politique de confidentialité et mentions légales personnalisables) avec trois choix : Tout accepter, Tout refuser, ou Personnaliser (statistiques / marketing séparément). Les deux premiers boutons ont volontairement le même poids visuel — c'est une exigence des recommandations CNIL 2020.

Le choix du visiteur est transmis à Google Tag Manager / gtag.js via le Consent Mode V2 standard (window.dataLayer) — le plugin ne contacte lui-même aucun serveur Google, il alimente juste le signal que votre GTM déjà en place sait interpréter.

⚠️ Le Consent Mode ne fait rien tout seul : GTM/gtag.js doit déjà être installé sur le site pour que ce signal serve à quelque chose.

Un lien « Gérer les cookies » peut être ajouté n'importe où (typiquement le footer) via le shortcode [navi_cookie_preferences_link], pour rouvrir la modale de préférences sans passer par le bouton flottant.

♿ Accessibilité

Sélecteur de langue, taille du texte, contraste, curseur, liens soulignés.

Ouvre un panneau permettant au visiteur d'ajuster son confort de lecture : taille du texte, contraste élevé, curseur agrandi, soulignage systématique des liens.

Le sélecteur de langue s'appuie sur WPML s'il est actif ; en son absence, il bascule automatiquement sur GTranslate si ce plugin est installé ; si aucun des deux n'est présent, le sélecteur de langue disparaît simplement (les autres réglages d'accessibilité restent disponibles).

🛒 Panier automatique

Panneau qui suit le visiteur sur la fiche produit, avec le prix et le bouton d'ajout au panier toujours visibles.

Fonctionne avec les produits simples et à variations (sélecteur de teinte inclus), compatible WCBoost Variation Swatches. Une chaîne de sélecteurs CSS de repli couvre le balisage WooCommerce standard et les thèmes les plus courants ; si votre thème a une structure inhabituelle, un réglage de sélecteur CSS personnalisé par champ (prix, nom, image) est disponible dans l'onglet Panier.

ℹ️ Compatible avec le template Produit du Site Editor (thèmes en blocs) — le formulaire de variations classique que le panier automatique détecte persiste sous les blocs. Seul le bloc expérimental WooCommerce « Ajouter au panier + Options (Bêta) », entièrement piloté en JS, n'est pas pris en charge tant qu'il reste en bêta.

🎬 Stories

Jusqu'à 4 bulles vidéo cliquables par produit — format YouTube ou MP4.

Sur la fiche produit, un onglet dédié « Stories » permet de configurer jusqu'à 4 emplacements vidéo : coller une URL ou un identifiant YouTube pour un aperçu immédiat, ou choisir une vidéo MP4 directement depuis la médiathèque WordPress.

ℹ️ Si le plugin compagnon Navi FAQ est aussi installé, Stories et FAQ partagent un seul panneau « Navi » (sous l'éditeur de description) avec un onglet interne par fonctionnalité, plutôt que chacune sa propre entrée dans « Données produit ». Sans Navi FAQ, Stories apparaît directement comme onglet « Stories (Navi) » dans « Données produit ».

Côté visiteur : sur ordinateur, un panneau s'ouvre avec un mockup de téléphone (100 % CSS, aucune image externe) ; sur mobile, la vidéo s'ouvre en plein écran façon story. Affiché automatiquement après la galerie produit par défaut, ou positionné manuellement via le shortcode [navi_stories] ou le bloc Gutenberg « Navi Stories ».

💡 Sans vidéo de prévisualisation personnalisée, la bulle affiche la vignette officielle YouTube de la vidéo. Pour une bulle animée (mini-vidéo en boucle), une prévisualisation MP4 peut être ajoutée dans les réglages avancés de chaque emplacement.

Apparence et visibilité

Depuis l'onglet Général de Navi > Navi :

  • Position du bouton : bas droite (par défaut) ou bas gauche — à changer si un autre widget flottant (chat, WhatsApp...) occupe déjà un coin.
  • Couleurs : couleur principale et secondaire, appliquées au bouton flottant et aux panneaux (cookies, accessibilité).
  • Arrondis : boutons et image produit (panier automatique), de 0 (angles droits) à 50px.
  • Langue du plugin : automatique (WPML/langue du site) ou forcée manuellement.

Chaque module a en plus, dans son propre onglet, deux cases « Afficher sur ordinateur » / « Afficher sur mobile » — pratique pour désactiver un module sur un seul type d'appareil sans le désactiver complètement.

Questions fréquentes

WooCommerce est-il obligatoire ?

Le cœur du plugin et les modules Consentement cookies / Accessibilité fonctionnent sans WooCommerce. Les modules Panier automatique et Stories sont liés à la fiche produit WooCommerce et nécessitent qu'il soit actif — un message s'affiche dans le Back Office s'il est absent ou désactivé.

Où sont stockées les vidéos MP4 des stories ?

Les vidéos de prévisualisation sont choisies ou importées via la médiathèque WordPress standard (le même sélecteur que partout ailleurs dans l'admin) : elles sont donc stockées comme n'importe quel autre média, jamais dans le dossier du plugin — ce dernier peut être écrasé à chaque mise à jour, contrairement au dossier des médias.

Le sélecteur de langue fonctionne-t-il sans WPML ?

Oui : si le plugin GTranslate est installé, le sélecteur bascule automatiquement dessus. Sinon, le sélecteur de langue disparaît simplement — les autres réglages d'accessibilité restent disponibles.

Le panier automatique fonctionne-t-il avec mon thème ?

Une chaîne de sélecteurs CSS de repli couvre le balisage WooCommerce standard et les thèmes les plus courants. Si votre thème a une structure inhabituelle, un réglage de sélecteur CSS personnalisé par champ (prix, nom, image) est disponible dans Navi > Panier.

Puis-je choisir où affichent les bulles Stories ?

Par défaut elles apparaissent juste après la galerie produit. Utilisez le shortcode [navi_stories] pour les placer ailleurs (contenu, constructeur de page, template de thème) — id="123" pour cibler un produit précis, ou vide pour le produit de la page courante. Pour éviter un doublon, désactivez « Afficher automatiquement » dans Navi > Stories si vous utilisez le shortcode.

Résumé technique

Architecture, pour l'équipe dev
  • Architecture modulaire : chaque module s'enregistre auprès d'un registre central (Navi_Module_Registry) et communique avec le bouton flottant via un événement JS générique (navi:action) — aucun module ne connaît les autres.
  • Fichiers : includes/core/ (registre, menu admin, frontend, i18n), includes/modules/<nom>/ (un dossier par module).
  • Traduction : toutes les chaînes passent par __()/_e() ; pas de fichier .mo, un dictionnaire PHP embarqué intercepte le filtre gettext (détection WPML, sinon locale du site, ou langue forcée dans Navi > Navi).
  • Assets : chaque script/style est chargé via wp_enqueue_script()/wp_enqueue_style(), jamais en inline — conforme aux exigences de revue WordPress.org.
